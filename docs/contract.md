# Native contract decision (development baseline)

Target observed versions: Pi 1.5.0 and Herdr 0.9.5 / socket protocol 22. This is not a compatibility or cross-platform certification. The repository has no selected KB; repository instructions, installed Pi docs and the versioned Herdr API govern.

- Pi's `agent_settled` is final notification; `agent_end` is not. A settled `aborted` turn (Escape) is held. `agent_before_settle` is Pi's final actionable in-run boundary; aborted runs skip it. This package observes `agent_settled` and receives later socket requests, then revalidates the live stop before injection. Error/compaction outcomes are not ordinary completed stops. `before_agent_start` distinguishes human input (`user`) from extension-authored custom messages. `session_start` gives new/resume/fork/reload, and `getSessionId()` identifies the native session, not the pane name. Session custom entries can persist local facts; they do not communicate between processes. `pi.events` is process-local, not a cross-process bus.
- Herdr already owns Pi state reporting; this package must not report a competing agent state. `HERDR_SOCKET_PATH`, `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID` identify the launched pane context. `agent.get` / `session.snapshot` return `terminal_id`, native `agent_session`, cwd, workspace, pane, status, `state_change_seq` and `completion_seq`. Those counters are **not** a durable stop identifier across server restart. Herdr `agent.prompt` accepts target and text but no expected session/stop precondition; its successful response cannot establish that the intended worker received/accepted work. A direct prompt is therefore not a safe continuation transport.
- Selected transport: a per-user private local handoff store for persistent intent/receipt, with separate single-writer supervisor records and worker-owned observations, plus a local worker-owned socket receiver in the Pi extension for addressed control envelopes. The socket is a delivery signal, not durable authority; read and reconcile records on session start and reconnection. Herdr socket subscriptions invalidate cached discovery, not replayable truth: subscribe first, then snapshot on a second connection, and refresh after overlapping events or `events_lost`. Protocol 22 requires `pane_id` for each `pane.agent_status_changed` subscription; bind them only to discovered registered panes and keep valid global pane invalidations for discovery. Follow Herdr's installed Pi integration's endpoint mapping: on Windows `\\\\.\\pipe\\${HERDR_SOCKET_PATH}`, otherwise the injected socket path, using Node `net`; never infer a Unix path. No model-written prompt or tool may activate, unpause, or rebind. A human command must explicitly authorize these changes.
- Stop identity must contain a worker-generated nonce, native Pi session ID, and current leaf/turn evidence, not Herdr `done`→`idle` alone. Worker observations must explicitly distinguish abort/error/approval hold; absent signal is unknown, not eligibility. Receipt handling revalidates native identity, current stop, and scoped activation *at execution*. A new human input invalidates an old stop. The worker listens to raw TUI input before Pi handles built-in menus and dialogs, holds immediately on any keyboard interaction after registration, and persists the hold. This covers user-initiated built-in UI but not programmatic extension prompts whose earlier event listeners stall. Persist intent before delivery, then receipt; on uncertain send/receipt persist suspension and require inspection rather than retry. Loss of the supervisor disables the worker receiver; a request already accepted before failure cannot be retroactively revoked.
- State ownership: one supervisor writes registrations, pauses, budgets, dispositions and intents; workers write observations and receipts only. One supervisor owner must be enforced across processes with real OS-backed exclusion. Never share a writable JSON document between roles. The model judges only checkpoint evidence and chooses among bounded disposition actions; code owns eligibility, nudge budget, deduplication, and escalation.

**Unverified:** no disposable credentialed Pi/Herdr runtime, Windows or macOS runtime was exercised in this investigation. The socket schema documents Windows named-pipe transport but does not give license to infer support from Linux tests. Approval holds without an explicit worker signal cannot be recognized as a hard boundary merely from model prose; such stops may be misclassified. Pi's `ui_prompt_start` notification is best-effort and not awaited before UI display. A worker whose hold listener is preceded by a stalled handler can accept a synthetic continuation under an open dialog; the same isolated probe rejects it when this extension is first. Registration and restore now require `-e <extension file>` as the first Pi option, ahead of discovered extensions and other explicit paths. This constrains one race but is not a general prompt-state API or proof of safe unattended approvals; programmatic Pi-owned interactions and prose-only requests remain to be verified or held. This package remains experimental: activation is disabled by default and the opt-in `PI_CONTINUATION_EXPERIMENTAL_ACTIVATION=1` is for separately authorized disposable testing only, not real workers, pending an enforceable prompt-hold boundary or independent approval gate. The installed Herdr Pi integration v9 reports `agent_session_path` when available, falling back to `agent_session_id`; it does not propagate `agent_settled.aborted` or provider errors. This initial package supports **saved Pi TUI sessions with a Herdr `path` reference only**: registration requires a session file, and supervisor binding compares its exact path. An ID-only Herdr reference is deliberately rejected rather than guessed/rebound; enabling it needs a separate identity-checked implementation. The integration may lag, so mismatch is a hold.

## Implementation boundaries

- `extension.ts` binds the three roles without starting resources. `session.mjs` reads native Pi identity; no role imports another role's lifecycle adapter for that fact.
- `supervisor.mjs` owns runtime resources, confirmations and effect ordering. `policy.mjs` owns deterministic disposition, budget, recovery and rearming transitions. Policy never performs I/O or grants activation. Resume intent is persisted before delivery; a confirmed receipt is required before recording delivery and consuming budget.
- `bindings.mjs` joins registered Pi identity with Herdr identity, rejects role/checkpoint collisions and enforces the pinned checkpoint path. `herdr.mjs` and `subscription.mjs` retain the native discovery/invalidation boundary.
- `ipc.mjs` owns local endpoint naming, bounded UTF-8 framing, one request per connection and listener cleanup. It never retries a delivery. Worker and coordinator acceptance stay in their respective receivers, including one-use receipt claims and the final live-state checks. Shutdown drains accepted handlers and closes incomplete peers.
- `contracts.mjs` defines shared durable record shapes and decodes supervisor snapshots and observations. These two records use `schemaVersion: 1`, independently of an observation's stop-generation `version`. Original unversioned records remain readable: old handled stops retain conservative no-resend guards and a missing hold is held. A missing generation is not invented. Malformed authority fields and unsupported format versions are refused, not treated as empty state. Other record shapes (registrations, owner lock, intents and receipts) retain their existing wire representation; live authority checks still belong to each recipient.
- `diagnostics.mjs` keeps the latest original cause in memory while reporting only role, operation and an allowlisted classification. No raw exception message, checkpoint content or filesystem path is emitted by this reporter. Failing closed is distinct from successful registration; observation persistence failure leaves the worker inert and reports an error.

Policy tests exercise transitions directly; local transport/persistence tests retain the actual effect and failure boundaries. Neither replaces the outstanding native-runtime acceptance below.

## Replacement acceptance

Source-level regression protection covers exact session/terminal/cwd routing, independent pause scopes, two-nudge bounds, one corrective attention turn, durable worker holds, one-use receipts, definite rejection versus uncertain delivery, material-notice disposition, cross-workspace coordinator routing, and worker/control-role/checkpoint collisions. Completion is a disposition, not independent acceptance; blocker/decision disposition pauses the worker even while its notice is deferred. Lost coordinator identity pauses its route, while worker/checkpoint loss stays worker-local. Returning identities never lift those pauses automatically. A completed observation with a missing or active hold can still surface for inspection, but cannot be acknowledged, resumed, or reported as completion. The worker receiver rechecks the persisted hold and exact observation after receipt claim; a changed or unreadable stop is not delivered. Completion freshness is checked both before dispatch and at the recipient, including after receipt claim; these near-delivery checks are not an atomic transaction with another process starting work. Pre-acceptance stale notices are discarded, while post-acceptance uncertainty remains suspended without retry.

Completion from narrative reports is a model judgment about the entire assigned backlog, not a string parser and not new user or approval authority. `acknowledge` and completion notices require a cleared hold, an exact idle stop and session, a cited excerpt in the pinned checkpoint, and the SHA-256 `reportHash` of the full file supplied in the attention message. An absent or changed hash rejects completion without consuming the stop. Queued completion notices compare the same report hash and hold before delivery and again at the coordinator, including after receipt claim. A pre-acceptance stale notice is discarded and its stop can be reassessed against the new report; an accepted but uncertain notice is never retried. A favorable verdict about one review, missing standalone marker, or incomplete follow-up is not by itself whole-task completion. The hash protects freshness, not semantic correctness; a model can still misread a report. The existing global workflow likewise relies on interpretation, but this extension is not ready for unattended real-worker activation until its separate approval boundary is enforceable.

These checks are not a claim that this package is ready to replace another supervisor. The full approval boundary, including programmatic and prose requests, still blocks real activation. Credentialed runtime and native platform verification, interrupted-delivery recovery, and an explicitly selected migration/rollback rehearsal remain prerequisites for replacement. Registrations from other supervision systems are not imported or inspected automatically; cross-registry duplicate ownership must be excluded by the separately authorized migration procedure. Do not run both systems over the same worker. No private skill implementation, registry, checkpoint or machine setup is part of the public package.

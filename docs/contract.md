# Native contract decision (development baseline)

Target observed versions: Pi 1.5.0 and Herdr 0.9.5 / socket protocol 22. This is not a compatibility or cross-platform certification. The repository has no selected KB; repository instructions, installed Pi docs and the versioned Herdr API govern.

- Pi's `agent_settled` is final notification; `agent_end` is not. A settled `aborted` turn (Escape) is held. `agent_before_settle` is Pi's final actionable in-run boundary; aborted runs skip it. This package observes `agent_settled` and receives later socket requests, then revalidates the live stop before injection. Error/compaction outcomes are not ordinary completed stops. `before_agent_start` distinguishes human input (`user`) from extension-authored custom messages. `session_start` gives new/resume/fork/reload, and `getSessionId()` identifies the native session, not the pane name. Session custom entries can persist local facts; they do not communicate between processes. `pi.events` is process-local, not a cross-process bus.
- Herdr already owns Pi state reporting; this package must not report a competing agent state. `HERDR_SOCKET_PATH`, `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID` identify the launched pane context. `agent.get` / `session.snapshot` return `terminal_id`, native `agent_session`, cwd, workspace, pane, status, `state_change_seq` and `completion_seq`. Those counters are **not** a durable stop identifier across server restart. Herdr `agent.prompt` accepts target and text but no expected session/stop precondition; its successful response cannot establish that the intended worker received/accepted work. A direct prompt is therefore not a safe continuation transport.
- Selected transport: a per-user private local handoff store for persistent intent/receipt, with separate single-writer supervisor records and worker-owned observations, plus a local worker-owned socket receiver in the Pi extension for addressed control envelopes. The socket is a delivery signal, not durable authority; read and reconcile records on session start and reconnection. Herdr socket subscriptions invalidate cached discovery, not replayable truth: subscribe first, then snapshot on a second connection, and refresh after overlapping events or `events_lost`. Protocol 22 requires `pane_id` for each `pane.agent_status_changed` subscription; bind them only to discovered registered panes and keep valid global pane invalidations for discovery. Follow Herdr's installed Pi integration's endpoint mapping: on Windows `\\\\.\\pipe\\${HERDR_SOCKET_PATH}`, otherwise the injected socket path, using Node `net`; never infer a Unix path. No model-written prompt or tool may activate, unpause, or rebind. A human command must explicitly authorize these changes.
- Stop identity must contain a worker-generated nonce, native Pi session ID, and current leaf/turn evidence, not Herdr `done`→`idle` alone. Worker observations must explicitly distinguish abort/error/approval hold; absent signal is unknown, not eligibility. Receipt handling revalidates native identity, current stop, and scoped activation *at execution*. A new human input invalidates an old stop. A completed stop also pins the assistant's final text reply (at most 8192 UTF-8 bytes); a missing/blank/oversized reply, including from an older observation, is held for inspection rather than silently ignored. The worker listens to raw TUI input before Pi handles built-in menus and dialogs, holds immediately on any keyboard interaction after registration, and persists the hold. This covers user-initiated built-in UI but not programmatic extension prompts whose earlier event listeners stall. Since a separate prompt after registration also holds, an optional JSON `--start` envelope supplies the first user message as part of registration confirmation. The registration and socket are provisional and reject delivery until observation and receiver setup finish; prompt/input/turn/session changes during setup cancel it without publishing an active worker or sending the user message. If session-entry append itself triggers an event, its entry remains inert without a synchronous ready marker, including when record cleanup fails. There is no await between the final live checks, ready-marker commit and native user-message dispatch. Pi's void send API does not establish delivery: a matching `before_agent_start` followed by `agent_start` is the initial-run signal. Until then, the observation is pending with no eligible stop; if the run is not observed within 30 seconds, the worker is held without retrying the uncertain message. A restart while pending restores a hold. It does not clear an existing registered worker hold or grant supervisor activation. Persist intent before delivery, then receipt; on uncertain send/receipt persist suspension and require inspection rather than retry. Loss of the supervisor disables the worker receiver; a request already accepted before failure cannot be retroactively revoked.
- State ownership: one supervisor writes registrations, pauses, budgets, dispositions and intents; workers write observations and receipts only. One supervisor owner must be enforced across processes with real OS-backed exclusion. Never share a writable JSON document between roles. The model judges the checkpoint and pinned final reply and chooses among bounded disposition actions; code owns eligibility, nudge budget, deduplication, and escalation.

**Unverified:** no credentialed supervisor/worker runtime, Windows or macOS runtime was exercised. Disposable Linux Pi/Herdr TUI sessions with a loopback scripted model verified final-reply capture, exact coordinator decision delivery and an explicit first turn with a completed, unheld stop; isolated interleaving tests cover provisional rollback. Disposable no-auth and handled-input Pi TUI trials left the first turn unstarted and held after the bounded wait. These do not prove real model interpretation or all UI prompt ordering. The socket schema documents Windows named-pipe transport but does not give license to infer support from Linux tests. Approval holds without an explicit worker signal cannot be recognized as a hard boundary merely from model prose; such stops may be misclassified. Pi's `ui_prompt_start` notification is best-effort and not awaited before UI display. A worker whose hold listener is preceded by a stalled handler can accept a synthetic continuation under an open dialog; the same isolated probe rejects it when this extension is first. Registration and restore now require `-e <extension file>` as the first Pi option, ahead of discovered extensions and other explicit paths. This constrains one race but is not a general prompt-state API or proof of safe unattended approvals. A synchronous shared-UI guard now fences overlapping dialogs on the runner's shared context, with revision checks spanning registration and hold clearing. Native Pi 1.5.2 TUI testing verified this improvement **and an uncovered alternate shortcut-context gap**: that UI object bypasses the wrappers and nested events, so first-option loading does not establish the required boundary. A blind model exercise selected acceptable dispositions on 12 synthetic narrative cases, not the complete supervisor runtime. See [the evidence and remaining limits](validation.md); programmatic Pi-owned interactions and prose-only requests still require full acceptance. This package remains experimental: activation is disabled by default and the opt-in `PI_CONTINUATION_EXPERIMENTAL_ACTIVATION=1` is for separately authorized disposable testing only, not real workers, pending an enforceable prompt-hold boundary or independent approval gate. The installed Herdr Pi integration v9 reports `agent_session_path` when available, falling back to `agent_session_id`; it does not propagate `agent_settled.aborted` or provider errors. This initial package supports **saved Pi TUI sessions with a Herdr `path` reference only**: registration requires a session file, and supervisor binding compares its exact path. An ID-only Herdr reference is deliberately rejected rather than guessed/rebound; enabling it needs a separate identity-checked implementation. The integration may lag, so mismatch is a hold.

## Implementation boundaries

- `extension.ts` binds the three roles without starting resources. `session.mjs` reads native Pi identity; no role imports another role's lifecycle adapter for that fact.
- `prompt-guard.mjs` owns shared-UI interception, external prompt revisions, owned confirmations and wrapper cleanup; `observation.mjs` pins those revisions through publication and hold clearing. Lifecycle events remain a fallback, not all-context observability. `attention.mjs` formats the supervisor's untrusted checkpoint/final-reply evidence without interpreting it.
- `supervisor.mjs` owns runtime resources, confirmations and effect ordering. `policy.mjs` owns deterministic disposition, budget, recovery and rearming transitions. Policy never performs I/O or grants activation. Resume intent is persisted before delivery; a confirmed receipt is required before recording delivery and consuming budget.
- `bindings.mjs` joins registered Pi identity with Herdr identity, rejects role/checkpoint collisions and enforces the pinned checkpoint path. `herdr.mjs` and `subscription.mjs` retain the native discovery/invalidation boundary.
- `ipc.mjs` owns local endpoint naming, bounded UTF-8 framing, one request per connection and listener cleanup. It never retries a delivery. Worker and coordinator acceptance stay in their respective receivers, including one-use receipt claims and the final live-state checks. Shutdown drains accepted handlers and closes incomplete peers.
- `contracts.mjs` defines shared durable record shapes and decodes supervisor snapshots and observations. These two records use `schemaVersion: 1`, independently of an observation's stop-generation `version`. Original unversioned records remain readable: old handled stops retain conservative no-resend guards and a missing hold is held. A missing generation is not invented. Older completed observations lacking the pinned final reply are held instead of resumed. Malformed authority fields and unsupported format versions are refused, not treated as empty state. Other record shapes (registrations, owner lock, intents and receipts) retain their existing wire representation; live authority checks still belong to each recipient.
- `diagnostics.mjs` keeps the latest original cause in memory while reporting only role, operation and an allowlisted classification. No raw exception message, checkpoint content or filesystem path is emitted by this reporter. Failing closed is distinct from successful registration; observation persistence failure leaves the worker inert and reports an error.

Policy tests exercise transitions directly; local transport/persistence tests retain the actual effect and failure boundaries. Neither replaces the outstanding native-runtime acceptance below.

## Selected-worker ownership handoff (source preparation)

`ownership.mjs` defines a generic per-worker witness shared with a separately prepared old-system adapter. Witnesses live only in the destination state root's canonical `ownership` directory, which the old adapter must also use. The key is SHA-256 of the canonical saved session path; the witness also pins the native session ID, canonical checkpoint, exact destination state root and worker ID, and a one-use handoff UUID. This is coordination between cooperating implementations, not protection against arbitrary programs running as the same OS user. A witness alone cannot stop an unmodified old supervisor. No active legacy adapter is installed by this package.

The caller of `prepareHandoff` must hold the old registry's existing lock for the entire operation. The old adapter must check the same witness before worker activation, continuation, attention and pending notices, including after restarts. Under a shared exclusive `mkdir` mutex, preparation first persists `prepared` (neither owner may act), reserves and pauses only the selected old worker through the private adapter, and finally persists `owned`. Errors never automatically roll back. Other workers and their timer remain untouched. The private adapter retains the complete selected worker's pauses, spent budget, history and pending actions; it must not publish private registry formats or contents with the package.

After a separately authorized transfer, `/continuation-supervisor handoff <JSON reference>` can attach that exact witness to a newly bound paused worker with an observed settled stop. This is not an automatic migration command: confirmation requires inspection of retained old state and outstanding notices. It activates no scope, marks the current stop handled/no-resend, and conservatively starts with an exhausted two-nudge budget against the current checkpoint. A later new stop still needs evidenced new progress before resuming. It does not silently reconstruct or redeliver old pending notices. A missing/changed witness or canonical identity prevents worker activation and receipt acceptance; an ownership loss pauses only that worker. New notices also check the fence, with a definite pre-delivery ownership rejection left pending rather than reported as uncertain delivery.

Availability observation reads the witness without taking the effect mutex, so it cannot mistake an in-progress activation/delivery for ownership loss; that read never grants permission. Activation and addressed delivery acquire the mutex and recheck ownership through their effects. Any addressed delivery attempt or notice delivery attempt sets a durable sticky `used` flag **before** the external effect, including attempts subsequently rejected or uncertain. Worker receipt handling still enforces all original exact-stop, approval, scope and one-use checks. This conservative flag never replenishes on restart. Bindings without an attached reference still acquire that same mutex and check the deterministic witness path. Any existing witness refuses unattached activation/delivery, so skipping the attachment command cannot bypass a transfer. A standalone external effect persists a conservative usage marker under that mutex; later preparation refuses that session until manual reconciliation, even if its session file has not yet changed. Standalone operation is not evidence that no unmodified external supervisor owns the worker.

`rollbackHandoff` runs under the old registry lock and the same worker mutex. It refuses used witnesses or changed session/checkpoint contents, persists `returning` to fence the new receiver, calls an idempotent private restoration of only the selected old worker **paused**, then persists `returned`. It never rearms either owner or overwrites sibling state. Session/report hashes detect observed independent progress, not an atomic transaction with human edits; rollback restores supervision metadata only, never session/report files. A crash or failed restoration keeps both sides fenced; `returning` may retry the same idempotent restoration. A used transfer needs manual forward reconciliation instead of old snapshot restoration. Completed witnesses are retained and cannot be overwritten by another preparation. Missing, malformed, unsupported or busy witnesses fail closed. A process crash can leave a mutex directory: no PID/age/socket-based lock stealing or automatic recovery is permitted; inspect pending effects before manually removing an abandoned lock. Never remove a live lock.

Temporary-storage Node tests exercise concurrent processes, interrupted preparation/rollback, unattached-transfer rejection, standalone/preparation exclusion, conservative no-replay/no-budget-reset attachment, receiver injection, and independent-progress rollback refusal. A private disposable copy of the old supervisor exercises selected-worker enforcement and sibling preservation against temporary registries and fake Herdr/systemd effects. This is source-level preparation, not live handoff acceptance or cross-platform runtime evidence. The old adapter still needs separately authorized installation, and a complete selected-worker preview/transfer/rollback runtime rehearsal remains required. Approval-boundary and platform gates below are unchanged.

## Replacement acceptance

Source-level regression protection covers exact session/terminal/cwd routing, independent pause scopes, two-nudge bounds, one corrective attention turn, durable worker holds, one-use receipts, definite rejection versus uncertain delivery, material-notice disposition, cross-workspace coordinator routing, and worker/control-role/checkpoint collisions. Completion is a disposition, not independent acceptance; blocker/decision disposition pauses the worker even while its notice is deferred. Lost coordinator identity pauses its route, while worker/checkpoint loss stays worker-local. Returning identities never lift those pauses automatically. A completed observation with a missing or active hold can still surface for inspection, but cannot be acknowledged, resumed, or reported as completion. The worker receiver rechecks the persisted hold and exact observation after receipt claim; a changed or unreadable stop is not delivered. Completion freshness is checked both before dispatch and at the recipient, including after receipt claim; these near-delivery checks are not an atomic transaction with another process starting work. Pre-acceptance stale notices are discarded, while post-acceptance uncertainty remains suspended without retry.

Completion from narrative reports is a model judgment about the entire assigned backlog, not a string parser and not new user or approval authority. `acknowledge` and completion notices require a cleared hold, an exact idle stop and session, a cited excerpt in the pinned checkpoint, and the SHA-256 `reportHash` of the full file supplied in the attention message. An absent or changed hash rejects completion without consuming the stop. Queued completion notices compare the same report hash and hold before delivery and again at the coordinator, including after receipt claim. A pre-acceptance stale notice is discarded and its stop can be reassessed against the new report; an accepted but uncertain notice is never retried. A favorable verdict about one review, missing standalone marker, or incomplete follow-up is not by itself whole-task completion. The hash protects freshness, not semantic correctness; a model can still misread a report. Final assistant text is also untrusted evidence tied to the same observation stop: an exact reply excerpt may justify a decision/blocker notice or pause, but never a resume or completion without checkpoint evidence. The existing global workflow likewise relies on interpretation. A model can still misread a prose-only approval request; this is not a deterministic guarantee against every such request, and real-worker activation remains out of scope.

These checks are not a claim that this package is ready to replace another supervisor. The full approval boundary, including programmatic and prose requests, still blocks real activation. Credentialed runtime and native platform verification, interrupted-delivery recovery, and an explicitly selected migration/rollback rehearsal remain prerequisites for replacement. Registrations from other supervision systems are not imported or inspected automatically; cross-registry duplicate ownership must be excluded by the separately authorized migration procedure. Do not run both systems over the same worker. No private skill implementation, registry, checkpoint or machine setup is part of the public package.
